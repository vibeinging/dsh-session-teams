# 对话目录和角色窗口团队

[English](2026-09-01-session-teams.md) | 中文

## 摘要

`@vibeinging/dsh-session-teams` 为同一 Host 可见的每个普通 DSH 对话提供按标题直接路由。Host 会在发送时恢复冷目标；一个用户直接请求还能创建多个由当前对话负责的命名顶层角色窗口，并用持久任务状态、依赖和有限重试安排它们工作。

实现中没有连接图、邀请授权或断开操作。只要对话仍在 DSH 持久存储中，就一直可以访问。用户用自然语言要求停止与某个窗口沟通时，由模型通过普通对话上下文遵守。

## 决策

官方 `SessionPersistence` 服务是持久对话目录。带版本的检查会折叠 `session/title` 和 `request/context`，实时 `AgentRegistry` 会覆盖当前活动状态。路由包含 Host 可见的每个顶层会话，准确标题重复时会拒绝；单条无法读取的持久会话会被跳过，不会阻塞应用启动或目录中的其他会话。

`send_window_message` 接受界面标题或可选准确链接。冷目标通过 `SessionController.resolveAgent()` 恢复，由它重新组装正常的 preset、工具、系统提示词、权限和已选模型，不会构造裸 Agent。模型编写的消息是持久的 `user/message` 事件，其 source 采用 user 外形，因此标准 Chat 会显示归属于发送窗口的普通气泡；曾实现过注册的非 user 种类并已回退，因为官方 Chat 会把注入的 context 节点折叠进默认收起的 turn-process 区域。非任务类转发文本自带一段固定的回复契约，指示接收模型用 `send_window_message` 回复且免填 `target_name`，与团队成员已经遵守的派单契约一致；协议解析器会剥离这段契约，客户端卡片也不显示它。人类直接授权采用官方人类来源规则：user 形状的 source 只有在字段限于官方词汇表——`kind`、浏览器提问关联字段 `rpcId` 和 Host 校验的 `clientTimeZone`——时才算人类请求，同时排除本插件的转发消息和任何其他生产者携带元数据的 user 外形消息，格式损坏的声明也会按失败关闭处理。正在工作的目标通过 `steer()` 在最近一步收到消息，空闲目标会开始一轮。自动调度的团队任务使用 `followup()` 开启单独的任务轮次，由模型判断下一条消息是否有帮助，不设置往返计数。普通回复使用当前轮次中最新的转发消息，正式任务结果则使用成员持久历史中最新的可信任务派单，因此后来的普通提醒或后续轮次不会覆盖任务身份。负责人当前的团队状态仍会在接受结果前核对团队、任务、任务归属和状态。

`create_window_team` 接受兼容的单任务简写或每个成员的完整 `tasks` 图，并在副作用前校验所有 id、跨成员依赖、数量限制和无环性。标题完全匹配且唯一的已有对话会被复用；如果有多个完全匹配项，会在改变任何成员前拒绝。只有缺少的成员会进入创建流程。可选的 ProductHost 会说明发起 Session 属于产品绑定还是只有 DSH 身份。产品绑定的负责人会让父进程创建 App 会话和项目绑定，只有 DSH 身份的负责人则直接调用 `SessionController.create()`。两条路径都会使用 `selectModel()` 和 `resolveAgent()`，因此官方 preset 负责完整工具与提示词组装，并通过控制器选中负责人的当前准确 provider、model 和明确设置的推理强度。不支持范围查询的旧 ProductHost 仍然作为产品权威路径，任何错误都不会触发另一条创建路径。成员创建失败会返回失败或 `partial`，不会删除普通持久对话。负责人 Session 恢复时，幂等的 Workspace 登记会补齐所有已知团队成员缺失的归属。

负责人 Session 中使用官方 `team/task` 形状的完整、仅写入日志的记录是团队任务的权威状态。插件命名空间选择器让这些记录不属于以该 Session 为根的隐式 Agent Team。每个新状态都会追加更高修订号，不进入或替换模型可见表面，因此不会增加 `replaceGeneration`，也不会开启新的请求序列。官方 Session Projection 把同一份可重建状态送到浏览器；`stateVersion` 变化只会丢弃不兼容的派生检查点，然后重新折叠持久日志。折叠过程会接受旧版插件来源 `snapshot` 消息和 `window-team/state` 值，但不会重写它们。这样既不会引入官方持久事件目录在重启后无法识别的仓库外 Session 事件类型，也不需要第二套数据库。调度器只认领依赖已完成的任务；技术失败可以在配置上限内重试，工作失败保留给负责人决定。人工转派只移动未执行、等待或失败的任务，不复制运行中和已完成工作。

浏览器同时读取 `useSessions`、`useInput`、`inputActions` 和 `useProjection('windowTeam')`。有团队时先显示目标、进度、成员、角色和任务状态，其他普通对话放在次级折叠列表中；没有团队时显示完整可对话目录。选择其他对话时，插件通过 `InputActions.setDraft()` 把对方的界面标题加到当前草稿前，关闭浮层并恢复输入框焦点；用户仍提交普通消息，由模型进行目标路由。浮层没有邀请、连接、断开或移除操作。可信转发消息会通过显示包装组件覆盖 Chat 的 `user` 和 `steering` 单元：无关消息继续使用原组件，合法转发消息会显示紧凑的来源标题栏，并通过准确的 Session Controller 操作打开发送方对话。Slot 声明会早于所有等待注入器完成组件登记而可见，因此包装组件会订阅 Chat 消息 Slot，等两个原消息组件都存在后再安装。这些客户端投影不会修改持久事件或模型可见表面。

包和 loader 分别命名为 `dsh-session-teams` 和 `session-teams`；界面文案仍为**窗口协作**。新转发消息使用 session-teams 包标识和信封；解析器仍接受持久 Session 历史中的旧版 window-link 标识和信封。

## 验证契约

聚焦测试覆盖持久目录过滤和缓存、通过 Session Controller 恢复冷会话、不写死工具列表的完整 preset 创建、当前准确模型选择、产品绑定创建、ProductHost 存在时只有 DSH 身份的创建、未知范围拒绝、重名拒绝、无历史状态直接发送、输入框目标插入、可跳转的转发消息卡片、原组件回退、来源缺失时的显示、人类授权的失败关闭处理、模型自主回复、经过普通提醒和后续轮次仍保留的任务派单、成员查询负责人持有的团队状态、通过普通消息工具提交团队结果、兼容的单任务创建、跨成员原子任务图、标题完全匹配且唯一的对话复用、多重同名在副作用前拒绝、Workspace 登记、依赖放行、技术投递重试、人工转派、官方 Host 收件箱投递、官方投影组合、仅日志团队状态重放、模型表面代次稳定、旧版快照兼容、团队优先浏览器视图、协议解析和重复抑制。

发布门禁还必须验证构建后的 Host 和客户端产物、包内容，以及真实 DSH Desktop 流程：完整重启后不经过连接步骤按标题发送；在负责人 Workspace 中创建带依赖的 Development 和 Testing 窗口；复用两个已有命名窗口，让十个有依赖的任务按照一个原子任务图在两者之间交替执行直到完成。验收必须确认负责人浮层随任务状态更新，并确认仅日志变更不会替换模型表面或拆分请求序列。

## 边界

插件不会在 Host 停止时排队，不跨 Host 路由，不复制会话记录，不从普通文本判断任务完成，不自动转派，也不删除对话。队列接受不代表工作完成；成员在最终一次 `send_window_message` 中设置 `task_outcome`，task id 由其持久历史中最新的可信任务派单提供。
