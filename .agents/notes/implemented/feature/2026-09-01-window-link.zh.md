# Agent Note: 经用户同意授权的跨窗口任务链接

Status: implemented

[English](2026-09-01-window-link.md) | 中文

## 问题

普通 DSH 窗口需要一个简洁地址，用户可以将它复制到另一个窗口，让后一个窗口把任务委派回前一个窗口。如果只使用会话 id 或由模型编造的地址，提示词内容就会成为范围不受限制的授权依据；如果另设消息代理，则会重复实现 Host 的实时 agent（智能体）注册表和收件箱生命周期。

## 决策

`@vibeinging/dsh-window-link` 是一个为公开 NPM 分发而打包的独立插件。浏览器操作会复制 `dsh://session/<session-id>`；只有当完整的目标链接出现在当前步骤中由用户直接输入的消息里时，`send_window_task` 工具才会接受该目标。插件使用官方 NPM SDK，通过 `cordis.patch.yml` 挂载，既不 fork，也不修改 DSH 源码。

该插件面向同一 Host 进程内的活跃普通会话。它通过 `AgentRegistry` 解析目标，并调用 `agent.followup()` 投递带有版本标记的用户角色信封。工具成功只表示队列已接受任务，不表示任务已执行或完成。

浏览器操作会先尝试 `navigator.clipboard.writeText()`。如果 Clipboard API 不可用或调用遭到拒绝，操作会继续创建一个临时的屏幕外 textarea，并调用 `document.execCommand('copy')`；只有两条路径都失败时才报告失败。这样，即使 Electron 嵌入页面拒绝现代 API 但允许文档复制，该操作仍然可用。

## 安全边界

授权依据来自当前步骤的会话事件，而不是只取决于工具参数。系统只认可 `source.kind === 'user'` 的直接消息，而且这些消息必须位于最新的 `step/start` 之后。插件上下文、更早的轮次或步骤、部分 id 和模型生成的链接都不授予任何权限。

转发信封以 `[dsh-window-link/v1]` 开头。当前直接消息中只要存在该标记，系统就会拒绝新的投递，因此接收方 agent 无法使用转发任务中的授权继续转发。系统也会拒绝没有 agent 的调用、向自身投递以及以 subagent 为源或目标的投递。

## 重复投递契约

每次投递都有一个 `message_id`。有界的进程内账本会让内容完全相同的重复投递共享首个 promise，并拒绝把同一 id 用于不同的目标与任务内容。账本会保留待处理条目；需要容量时，它会清除已完成的回执，并在插件 dispose（资源释放）时清空。该 id 是用于审计和同进程重复检测的键，不是跨重启持久保存的回执。

## 备选方案

**fork 现有链接插件。** 不予采用，因为该插件必须保持独立所有权，而且现有的纯链接实现只提供复制和快照行为，不提供 DSH 工具、当前轮次授权、投递回执或 Cordis dispose。公开的 `dsh://session/<session-id>` 形式保持兼容，无需继承该代码库。

**添加消息代理、SQLite 队列或轮询服务。** 不予采用，因为活跃会话已经具有权威注册表和收件箱。第二套队列会引入同步、清理和信任边界，却无法改进同一 Host 场景。

**接受模型提供的任意目标。** 不予采用，因为模型上下文可能包含不可信或陈旧的链接。要求完整链接出现在当前用户直接消息中，可使每次投递都获得一次显式、严格限定范围的授权。

**恢复冷会话。** 此版本暂不采用，因为向非活跃会话投递任务，需要实时 `AgentRegistry` 未提供的持久化会话归属、恢复和路由规则。不能用第二套队列或源码检出依赖替代这一生命周期边界。

## 验证

聚焦测试固定验证严格解析、当前步骤授权、插件上下文排除、转发阻断、普通会话检查、队列文案、重复调用共享与冲突、浏览器 Clipboard 请求被拒绝后的降级处理，以及最终复制失败反馈。真实的 Cordis Loader 组合会装配 DSH `0.1.2-alpha.3` 的 `SystemPrompt`、`ToolRegistry`、`AgentRegistry` 和该插件，然后验证已注册的 `send_window_task` schema。公开包通过 `prepublishOnly` 运行完整检查；Host 与浏览器构建和经过审计的包内容都不包含 DSH 源码检出路径或本地依赖协议。

## 结果

用户获得了简短且直观的流程：复制目标链接，将链接与任务一并粘贴，然后让源 agent 调用一个工具。授权范围明确，并且无法通过转发消息自动传播。

只有同一 Host 进程中的活跃普通会话可以访问。系统会明确拒绝非活跃或远程窗口；回执会随进程重置；若要确认目标是否完成任务，需要另行设计回复或状态协议。未来的冷会话实现需要官方提供持久化会话归属与路由 seam；无需扩大链接或授权协议的范围。
