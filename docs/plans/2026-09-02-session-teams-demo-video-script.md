# dsh-session-teams 演示视频脚本

## 演示目标

用一个约 2 分钟的“折扣规则开发与验收”场景，同时展示两个真实对话窗口、一对多团队、任务依赖、自动接力、真实消息、双向回复和点击窗口后直接输入对话。开发任务只使用 Node.js 内置能力，不需要下载依赖，适合重复录制和回归测试。

## 录制前准备

- 使用一个可丢弃的空工作区，避免演示文件进入产品仓库。
- 新建一个普通对话并命名为“折扣产品负责人”。
- 确认左侧列表中没有同名的“折扣·开发”和“折扣·测试”。如果已存在，给两个名称加上同一个日期后缀。
- 将工具调用详情保持折叠，录制重点放在对话列表、消息和窗口团队浮层。
- 完整录制执行过程，剪辑时将等待模型的片段加速到 4 至 8 倍，保留状态切换前后各 1 秒。

## 首条演示指令

在“折扣产品负责人”中粘贴并发送：

```text
你是产品负责人。请创建两个真实窗口，并协调到验收完成：

1. “折扣·开发”：在 demo/discount-rate.mjs 中实现并导出 discountRate(total)。0 到 99 返回 0，100 到 199 返回 0.1，200 及以上返回 0.2，负数抛出 RangeError。不要使用第三方依赖。
2. “折扣·测试”：必须等开发完成后再开始。使用 Node.js 内置 node:test，在 demo/discount-rate.test.mjs 中覆盖 0、99、100、199、200、1000 和 -1，然后运行 node --test demo/discount-rate.test.mjs。
3. 你只负责拆分、调度和汇总，不要代替成员写代码。测试通过后，让测试窗口把结果发回这里，再告诉我最终文件、测试命令和结果。
```

## 追问文案

点击“折扣·测试”后，输入框已有目标前缀，只需继续输入：

```text
请说明 199 和 200 为什么属于不同折扣档，并把一句话结论发回这里。
```

## 验收清单

- 左侧列表出现两个可打开的普通对话，不是只出现在工具结果中。
- 负责人浮层同时显示两个成员、角色、任务和 2 / 2 进度。
- 测试任务在开发任务完成前保持等待，完成后自动开始。
- 负责人发给成员的内容出现在成员的消息列表中，成员回复也出现在负责人的消息列表中。
- 点击成员后，准确标题进入输入框，输入框获得焦点，已有草稿不会丢失。
- 追问能投递给同一成员，成员完成后能再次通知负责人。
- 点击收到的消息来源后，页面跳到准确的发送方窗口。
- 整段操作不使用 Session ID、深度链接、连接或断开操作。

## 剪辑建议

开头展示一次完整用户指令，中间只保留“窗口出现、状态切换、真实消息、回复返回”四类画面，不需要长时间展开工具参数或日志。结尾定格在点击来源后跳到测试窗口，并显示一句总结：“创建真实窗口，自动协调任务，完成后继续对话。”
