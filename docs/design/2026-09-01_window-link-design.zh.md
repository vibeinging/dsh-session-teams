# DSH 窗口链接设计

[English](2026-09-01_window-link-design.md) | 中文

本参考文档定义 `@vibeinging/dsh-window-link` 负责的协议、授权、投递和浏览器边界。

## 范围

该插件面向同一 DSH Host 进程内的活跃普通会话。它公开一个浏览器操作，用于复制当前会话链接；同时公开一个面向模型的工具，用于向另一个活跃会话排队投递任务。它不会创建共享数据库、消息代理、远程网络服务，也不会对 DSH 源码打补丁。

## 链接和信封协议

规范链接为 `dsh://session/<percent-encoded-session-id>`。解析器也会读取兼容的 `?v=1` 后缀，但序列化时会省略该后缀。解析器会拒绝凭据、额外路径段、片段、其他查询字符串、控制字符、空白字符、路径分隔符、格式错误的百分号编码，以及解码后超过 512 个字符的 id。

目标会话会收到一条以 `[dsh-window-link/v1]` 开头的用户角色文本消息。该信封记录 `message-id`、`source-link`、`target-link`、投递仅表示进入队列这一语义、禁止转发规则和任务文本。版本标记使目标会话事件日志能够还原模型可见输入，并为后续协议版本提供显式判别字段。

## 授权

该工具读取调用方 agent（智能体）的权威事件日志。它找到最新的 `step/start`，并且只考虑该边界之后的 `user/message` 事件，其中 `source.kind` 必须为 `user`。请求的目标会话 id 必须与这些文本块中解析出的完整链接一致。

该规则只对当前步骤授予一个目标的访问权。更早的消息、插件生成的上下文、部分 id 和模型编造的链接都不授予投递权限。只要当前直接消息包含 `[dsh-window-link/v1]`，系统就会拒绝投递，从而防止目标 agent 将转发信封用作继续转发任务的授权依据。

调用方必须是归 agent 所有的普通会话。目标必须是另一个普通会话。工具会拒绝没有 agent 的调用、向自身投递、subagent 源会话和 subagent 目标会话。

## 投递和重复抑制

插件通过官方 `AgentRegistry` 解析目标。注册表中没有对应项时，系统会明确以 `target-not-active` 拒绝投递。对于活跃的普通目标，`agent.followup()` 会将带有标识的用户消息同步送入目标收件箱，并唤醒其驱动程序。

`accepted` 工具结果表示队列边界返回时未抛出异常。它不说明目标轮次何时开始、模型能否成功执行，也不说明请求的工作是否完成。

每次调用都带有 `message_id`；模型省略该值时，工具会生成一个。`DeliveryLedger` 会为每个 id 保存首个 promise，以及完全匹配的目标与任务指纹。完全相同的重复调用共享首次结果；系统会拒绝同一 id 对应不同内容。该有界账本会清除已完成的回执；需要容量时，它会拒绝新 id，而不会清除执行中的工作。账本只存在于进程内，并会在插件 dispose（资源释放）时清空。

## 浏览器集成

浏览器入口注册到 `conversation.session.header.actions`，并从标准会话 slot 属性中接收 `sessionId`。它向用户提供的操作名为**跟另一个窗口对话**。它会序列化规范链接，通过浏览器 Clipboard API 写入剪贴板，同时以 `execCommand('copy')` 作为降级方案，然后提示用户将链接粘贴到另一个窗口。其 CSS 和链接图标会打包到 `lib/client.js` 中；浏览器产物在运行时只导入 React。

## SDK 和包边界

本包面向 DSH `0.1.2-alpha.3`。DSH 功能包的 peer 依赖使用这一版本；Cordis `4.0.2`、Cordis Loader `1.0.3` 和 Schemastery `3.18.2` 是官方兼容的基础包版本。alpha.3 客户端入口使用 Cordis 客户端上下文和 `dsh.client` 包元数据。运行时和 TypeScript 路径都不会解析到 DSH 源码检出目录。

## 当前限制

此版本不支持向冷会话投递任务。恢复或路由非活跃会话，需要在实时 `AgentRegistry` 之外制定持久化的会话归属和生命周期规则。插件保持活跃窗口契约，不会另建一套持久化和路由系统。
